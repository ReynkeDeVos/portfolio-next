# Recruiter navigation and first-glance priorities

Reviewed on 2026-10-01. Research only; no interface changes.

## Recommendation

Use **Work → Career → Skills → Workflow**, with **Work as the default**.

This is an editorial recommendation for Renke's existing layout, not an experimentally established ordering. The persistent identity panel already answers who he is, where he is, his principal technologies and his current employment. The main panel can therefore provide immediate project evidence. Career should follow because it supplies employment chronology and professional context that the sidebar cannot fully provide. Skills expands the compact capability summary. Workflow provides personality, tools and interests after the qualification evidence.

## What the sources establish

- **GitHub's official hiring-oriented profile guidance** recommends a short professional bio, technical skills, experience and a small selection of prominent projects. It advises highlighting 3–5 projects, choosing relevant examples, and making their descriptions, demonstrations and code easy for hiring managers to understand. This supports a focused Work landing view, rather than a large repository inventory. It does not compare portfolio tabs. [GitHub Docs](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)
- **Amazon's own recruiters** recommend straightforward, well-organized, concise presentation and emphasize relevant actions, accomplishments and results over generic responsibilities. They also acknowledge that not every accomplishment has a numerical measurement. Applied here, project and career copy should explain what Renke actually did and what the software enables, using verified metrics only. This advice concerns resumes, not website ordering. [Amazon recruiting advice](https://www.aboutamazon.com/news/workplace/amazon-job-application-resume-writing-tips)
- **Microsoft recruiter Joel Havermans** advises retaining relevant experience even when prior roles do not directly match the desired role, explaining transferable skills, and using a succinct headline and bio. This supports keeping the instructor role visible and explaining its development, problem-solving and communication relevance. It does not justify relabeling teaching experience as commercial software production. This is first-party advice from 2018, not current quantitative research. [Microsoft recruiter advice](https://news.microsoft.com/life/resume-experience/)

## First viewport: proposed priorities

The following hierarchy is an inference from those principles and this portfolio's content:

1. **Identity and professional orientation:** Renke Brixel, software developer, portrait, Hamburg, Germany. Add one compact sentence describing the kind of software he builds, rather than a generic statement of enthusiasm.
2. **Quick capability and employment context:** React/TypeScript, C#/.NET, Python and Linux; current software-development instructor role with its confirmed start year. Keep development as the primary identity while making employment unambiguous.
3. **Concrete work:** visible project titles, plain-language purposes and compact technology labels. The three verified examples establish C#, Python and Linux work: Reputation Assistant, Scoundrel TUI and Omarchy System Stats. At least the first project should show a useful description and a visible route to implementation details or its repository without opening another tab.
4. **Immediate next steps:** recognizable email, GitHub and LinkedIn links, plus clearly visible Career navigation. If a current, approved downloadable CV exists, expose it directly; the research does not establish that such a file is ready.

React/TypeScript is listed prominently but is not demonstrated by the three primary projects. Make the additional web examples easy to discover from Work. For a specifically frontend-oriented audience, promoting the verified React example could improve relevance; this portfolio currently addresses several audiences and has no active job-search positioning.

Do not require all project details, full employment history or the entire skill inventory to fit above the fold. The desktop panel should reveal evidence while the sidebar supplies orientation. On narrow screens, preserve identity and contact access and move into Work promptly.

## Evidence limits

These three primary sources support content priorities, not a measured conversion improvement, fixed attention span, or exact navigation sequence. No source here proves that Career must precede Skills. **Work → Skills → Career → Workflow** is also defensible if visitors chiefly explore technologies; Career second is my recruiter-oriented preference because the sidebar already summarizes skills. Validate the choice through brief tasks with actual recruiters: identify current role, find a relevant project, locate career history and find contact information.
